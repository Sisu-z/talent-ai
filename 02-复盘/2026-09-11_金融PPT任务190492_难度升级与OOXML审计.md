# 金融PPT任务190492：难度升级与OOXML审计复盘

- 日期：2026-09-11
- 专业领域：金融与会计
- 任务类型：金融PPT任务设计、模型难度控制、参考答案质检
- 状态：部分验证
- 关键词：A03、Gamma、集中度附加、原生图表、OOXML、Rubrics、Data、Trace、精度

## 背景与目标

为TalentsAI题号190492制作一套真实、可复算、可客观评分的银行ALCO任务，使两份模型输出都不高于65%，同时保证GT在金融逻辑、可见答案和文件结构层面能命中全部正分项。

## 问题表现

1. 旧版本A/B得分过高，单纯增加小数位无法形成真实区分度。
2. 单独加入无抵押零售集中度附加后，最优解可把相关权重压到8%而令附加归零，新增难度有限。
3. 初版评分表使用2/4/6/7/9/10分，不符合平台正分只能1/3/5的硬约束。
4. GT图表能渲染，但内嵌工作簿改名为Data后，图表公式仍引用旧的Chart Data。
5. 第4页瀑布桥基座是白色实填充，不是真正透明。
6. 部分H金额在容差内但显示位数不足；候选实际增速只显示2位，不满足±0.0001个百分点容差。
7. 第8页部分鲁棒结果存在于备注或隐含关系中，没有全部直接显示。
8. 浏览器控制会话偶尔过期，暂停前模型事务长时间处于processing，保存按钮因模型未完成而拒绝。

## 影响

- 若人为压分，会造成评分不诚实并在人工质检中暴露。
- 若评分权重非法，规则无法在平台稳定录入。
- 若图表公式断链，PowerPoint刷新或编辑数据时可能修复文件，参考答案审计分也会丢失。
- 若只看数值误差不看显示规则，GT会在严格二元评分下失分。
- 若在模型未完成前运行参考答案检测，会浪费极少的检测机会。

## 根因

- 难度最初主要集中在可见计算，模型容易复现；缺少跨附件、全网格重新优化和文件级审计要求。
- 生成工具在最终器阶段会重新物化图表工作簿，后处理若只改工作簿Sheet名而不改chart XML，会产生缓存可见但公式断链的“假正常”。
- 本地规则设计没有最先对照浏览器分值枚举。
- 精度检查只关注容差，没有把“至少显示几位”作为独立检查项。

## 解决过程

1. 新增A03集中度附加和Gamma参数风险预算，并复算Gamma=0至3的全部0.5个百分点网格。
2. 把Gamma=2定义为P^rob，要求最坏产品、U、ΔEL、ΔRWA和两条资本路径同时勾稽。
3. 把评分表重构为62条：正56、负6、正分200，所有分值映射到1/3/5和-5/-10。
4. 在PPTX后处理中同步修改chart XML公式为Data，并逐点比较公式引用范围、Data和缓存。
5. 将桥接图基座与线条改为OOXML `noFill`。
6. 把第7页H统一为6位小数、实际增速统一为4位；把第8页鲁棒资本、RWA和两条等式放入可见区。
7. 用包完整性、布局、首方导入、逐页渲染和独立交叉审查复核GT。
8. 对浏览器会话采用固定任务URL恢复和事务ID只读查询；暂停时不重跑模型、不消耗参考答案检测。

## 最终解决方案

当前v4正式包由A01、A02、A03和10页GT v20组成；评分表62条、正分200。GT包含5张原生图表、12张原生表格、10页备注、Alt Text以及5个Data/Trace内嵌工作簿。暂停时模型A/B仍在生成，平台最终难度结果尚待恢复后验证。

## 验证证据

- GT包结构检查：0问题。
- 布局检查：0问题、0警告。
- 5张图表共24个公式全部引用Data，公式范围、Data与缓存一致。
- 第4页透明基座和线条均为 `noFill`。
- 第6页底线为独立图表系列；第9页为原生XY散点图。
- 第2至第10页备注四标签齐全；目标图表和表格Alt Text齐全。
- Microsoft PowerPoint实机打开和平台最终检测尚未验证，因此整体状态为“部分验证”。

## 下次如何提前避免

1. 出题前先读取平台控件的合法分值、次数和文件上限，再设计规则表。
2. 模型难度优先来自新信息、新约束和可复算链，不来自模糊审美或人为压分。
3. 任何工作簿Sheet改名都必须同步检查chart XML公式、缓存和工作簿关系。
4. 质检同时检查数值容差、显示位数、单位、可见性和可编辑性。
5. 参考答案检测前冻结题面、附件、GT、规则和哈希，并先完成A/B人工取证。

## 可复用检查清单

- [ ] 正负分值只使用平台允许枚举，总分与条数复算正确。
- [ ] 两个模型分别独立评分，不能用GT或另一个模型补证。
- [ ] 高难度来自客观、可复算约束；不得人为漏判命中。
- [ ] 图表为目标原生类型，内嵌工作簿、公式、缓存和Data一致。
- [ ] 备注、Alt Text、表格和图表均满足可审计要求。
- [ ] 既检查数值容差，也检查至少显示位数。
- [ ] Reference check前完成本地全量QA并冻结哈希。
- [ ] Microsoft PowerPoint实机打开后再提交。
