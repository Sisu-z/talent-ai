# TalentsAI 平台外部经验参考

> 调研日期：2026-09-10  
> 样本范围：用户指定的 6 篇小红书笔记、页面当前可见评论、部分配图，以及 TalentsAI 当前公开《用户协议》。  
> 用途：把外部经验转成可执行的选题、出题、质检、止损和证据留存方法。  
> 重要提醒：本文件不是平台官方指南，也不是法律意见。项目规则会变化，真正提交前必须以当期任务说明、培训文档、《数据提交用户协议》和页面提示为准。

## 一、先说结论

TalentsAI 的核心不是“写出一道专业题”，而是同时完成四件事：

1. 题目必须来自真实、熟悉、可合法使用的专业场景；
2. Prompt、材料和评分标准必须足够封闭，使答案能够唯一收敛并被机械核验；
3. 题目还必须稳定暴露目标模型的能力缺口，达到项目规定的失败阈值；
4. 最终还要通过平台或客户验收，只有验收合格的成果才进入计费基数。

因此，真正决定收益的不是页面标注的“单题价格”，而是：

> 有效时薪 = （通过概率 × 单题结算 + 奖励期望 − 其他成本）÷ 全部主动投入时间

外部样本同时出现了两类真实但彼此不矛盾的结果：有人投入 6—11 小时后零收益，也有人通过题目、收到奖金或累计提现。正确策略既不是把平台简单判断为“必赚”，也不是仅凭负面帖子认定“必然白做”，而是小样本试跑、严格止损，只做自己有结构化优势的项目。

## 二、证据等级与阅读方式

本文按以下等级使用信息：

- **A 级：官方公开规则。** 可作为当前规则依据，但具体项目说明仍可能补充或改变操作要求。
- **B 级：作者正文与配图直接展示的本人经历。** 能证明“该作者遇到过什么”，不能推出整体通过率或所有用户都会如此。
- **C 级：评论区个人经历。** 可用于发现重复风险和候选技巧，不能当成统计结论。
- **D 级：作者或评论者的原因推断、法律评价、营销判断。** 只作为待验证假设，不写成已证实事实。

特别是“平台故意逐轮卡人”“不合格数据已被用于训练”“无法注销”“宣传帖均有报酬”等说法，目前样本不足以独立验证。它们值得防范和取证，但不应直接定性。

## 三、六篇外部样本逐篇提炼

### 1. 《下班搞 TalentsAI 一个月，踩过的坑劝你们别踩》

来源：[小红书原帖](https://xhslink.cn/o/7jOYjLWBhtE)

作者自述下班后做了约一个月，认为常见失败点不是学历或专业能力不足，而是只快速看完培训材料、完成约 10 道选择题，却没有真正理解案例背后的失误机制。作者早期投入大量时间和模型反复对话，但没有复盘，主观感受是“每天都在做、实际没有积累”。

可复用信息：

- 培训文档中的案例不是装饰，每一句限制都可能对应模型常见失误或质检员的验收点；
- 不能把“花了很久”当作“做得有效”，每轮都要形成可复用的失败模式记录；
- 多轮对话中，相似或冲突指令可能出现“偏向最新要求、遗漏旧约束”的现象，可作为候选测试方向；
- 先拆规则、再找模型弱点、最后设计题目，比无目标地反复试问有效。

可信度判断：方法论有价值，但“约 10 道题”“模型一定优先满足最新要求”等属于作者所处时期和任务的个人观察，不能视为长期不变的平台机制。

### 2. 《刚在 Talents AI 出完题，整个人卡在原地懵住》

来源：[小红书原帖](https://xhslink.cn/o/8yDs2KpQW50)

作者自述：先花 1 个多小时阅读规则，完整投入接近 6 小时，经历多轮修改；在评分规则阶段反复调整，仍遇到新的质检问题。作者最困惑的是：理解型任务天然允许情境判断，如何定义唯一标准答案；以及为何质检问题没有一次性给全。

作者总结的实操建议：

- 不要直接空想，先研究平台提供的已通过样题，抽取结构而不是复制内容；
- 首次提交前，手工模拟至少 3 种模型可能跑偏的输出，把可预见的发散方向写进边界条件；
- 对“必须做什么”和“明确不能做什么”都给出规则；
- 遭遇返修时保留规则版本和质检意见，避免只修当前表面问题。

评论区信号：

- 有人建议长文项目相对可做，指令遵循项目更容易卡在失败阈值；
- 有人同样在最后阶段被多次打回并放弃；
- 有人认为 Prompt 必须同时写明正向任务和禁止事项；
- 有评论提出“账户有余额时无法注销”等问题，但这与当前公开《用户协议》所写的注销渠道并不完全一致，必须单独实测并留证。

配图没有提供额外质检证据，主要是情绪化封面，因此本文不把封面当成事实证明。

### 3. 《Talent ai 我很无语》

来源：[小红书原帖](https://xhslink.cn/o/3nj9kueBtwE)

这是一个典型的“题目逻辑成立，但模型不够容易错”的失败案例。作者第一版用了角色设定、约束和十几轮对话；第二版加入格式冲突、撤销指令、无关话题干扰和跨轮记忆；第三版加入跨行对应关系，以及“修改 A 时必须同步 B”的联动规则。第三版终于让模型错两处，但 18 条评分标准中模型仍通过 16 条，作者计算正确率为 89%，未达到当时任务要求的“低于 70%”，最终在约 7 小时、3 版对话后止损放弃。

这个案例说明：

- “题目复杂”不等于“模型会错”；
- 评分项拆得越多，如果多数是模型轻易满足的低难度项，整体正确率反而越高；
- 真正有效的是高耦合、跨位置、跨轮次、需要同步更新的约束，而不是单纯增加对话长度；
- 必须在正式写完整题目前先验证核心失败机制，否则会在低价值的措辞和格式上浪费时间。

评论区形成了几个相互制衡的信号：

- 有人自述通过 7 题且到账较快；
- 有人自述一题长文投入约 11 小时才通过；
- 有人建议关注多模态阅读理解、复杂环境交互、API/MCP 调用等模型弱点；
- 也有人认为要求两个模型同轮失败会导致大量试错；
- “模型会根据返修信息学会知识点”“平台吸收失败成果”等属于用户推断，不能仅凭输出变化证明模型被线上训练。

### 4. 《白嫖你的智力和时间》

来源：[小红书原帖](https://xhslink.cn/o/51zLtOyJFAy)

作者自述在法律场景中出题，投入约 6 小时、修改 3 轮后未结算。其主要抱怨可分为四类：

1. 平台要求半封闭或封闭，但法律问题天然包含事实判断和裁量空间，作者认为验收标准主观；
2. 质检没有一次性提出全部问题，后期才出现对题目基础结构的否定；
3. 未通过即无收入，但题目、文件、标准答案已被提交，作者担忧成果去向；
4. 作者声称部分社交媒体宣传帖可能获得平台报酬，因此提醒识别利益关系。

评论区有重要反例和补充：

- 一名用户自述两个月抽空做题收入 2,000 元以上（含激励），同时承认实际时薪明显低于页面标价、返修耗时且质检严格；
- 另一名用户自述早期三四个月累计一万多元，并认为熟悉套路后会改善；
- 有用户提到，两个曾经有效的指令遵循技巧重复使用后会被判同质化；
- 有人认为偏理工科、规则更封闭的背景更适配；
- 有人反馈申诉入口、申诉理由和返修机制不够清晰。

关键判断：该帖能证明部分用户对不透明验收和零报酬失败成本有强烈不满，但不能单独证明平台将未通过成果用于训练。TalentsAI 当前公开《用户协议》反而明确写有“未验收合格成果不用于模型训练，但验收、反作弊、风控和合规审查所需处理除外”。两者存在证据冲突，实操上应以留证、申诉和最新书面规则为准。

### 5. 《AI 数据标注｜小白也能学会让 AI 犯错的 idea》

来源：[小红书原帖](https://xhslink.cn/o/1lIKHk9z9AG)

作者是理学硕士，自述做多轮指令遵循接近一个月，给出两类测试思路：

- **字数陷阱：** 分轮设置全局字数限制与局部固定字数，再叠加扩写、缩写，测试模型是否遗忘局部规则；
- **格式陷阱：** 先设置斜体、下划线、删除线、加粗等规则，后续增加表格或新内容，测试新增部分是否遗漏格式。

作者还强调：

- 条件应分轮发布，以测试跨轮保持能力；
- 先想好失败点和提问顺序，再开始正式对话；
- 选择自己熟悉的业务场景；
- 一个实际题目曾把长文本和表格组合起来。

配图可见一份平台页面，显示“Rubric 正确率 53.8%（需 ≤70%）”，两个模型区域均显示 0.0 分。它能佐证作者至少做出了满足某个模型失败阈值的中间状态，但不能单独证明最终通过人工验收或已经获得题目结算。

评论区还提示：

- 电脑端是主要作业环境，手机可浏览项目；
- 作者不建议直接让其他 AI 代写题目，并称系统会判不合规；
- 具体项目是否允许任何生成式 AI 辅助，必须查当期规则。当前公开《用户协议》禁止使用未经授权的生成式 AI 工具交付任务。

### 6. 《在 Talents ai 做阿加莎长文项目的一些心得》

来源：[小红书原帖](https://xhslink.cn/o/5GTJ63hXyME)

这是六篇中信息最完整的正向案例。作者自述通过初步测试后开始阿加莎二期长文项目，连续 4 天、每天约 2 小时才通过 AI 质检，之后又被专家质检打回两次；评论中还说 AI 质检阶段接近 10 次。最终题目通过并结算，另有奖金。

配图补充了正文没有说清的细节：

- 机会申请页面显示：工业与制造、Excel 高阶任务设计、Agentic Coding 计算力方向三项“申请失败”，另有一项通用指令遵循岗位处于“已申请”；
- 另一张短信截图显示某岗位申请通过；
- 审核通过短信明确显示阿加莎长文题目已通过；
- 钱包截图显示累计收入和累计提现均为 625 元、当前可提现为 0 元，说明该账户确实发生过收入与提现；
- 短信截图显示返修有明确截止时间，逾期会自动废弃且不结算；
- 机会页展示的任务报价差异很大：通用任务约 100—200 元/任务，部分 Coding 类任务展示 500—1,000 元/任务并附推荐奖励。报价不是到手时薪，且作者并未通过所有高价岗位申请。

作者的长文出题流程：

1. 选择业务场景，如政策变更下的规则适配、合同审查、财务核对；
2. 准备贴近真实工作的材料，删除真实身份信息，同时保留自然冗余、格式噪声；
3. 把 Prompt 封闭化：材料边界、版本映射、字段顺序、枚举代码、冲突优先级都写清；
4. 构造唯一收敛的证据链：旧值、修订说明、新值缺一不可；
5. 让 Trajectory 与 Answer 对齐：思考路径说明每份材料怎样参与推导，最终答案严格按格式输出；
6. 提交后按返修截止时间处理，避免题目自动废弃。

合规修正：帖子建议从网上搜集公司政策公示文件并修改，但“公开可见”不等于“可以无限制复制进商业训练任务”。材料必须经过授权、许可或充分改写与匿名化，且不能包含个人信息、商业秘密、受限数据或未经许可的第三方知识产权。

## 四、六篇内容的统一分类

| 分类 | 高频现象 | 对玩家的含义 | 优先动作 |
|---|---|---|---|
| 规则理解 | 看完文档仍不会出题；项目规则层层叠加 | 入门测试通过不等于理解验收逻辑 | 把规则改写成可核验清单 |
| 题目封闭性 | 法律、咨询、解释类问题容易发散 | 专业深度如果无法唯一判分，反而是风险 | 先定义唯一答案，再写场景 |
| 模型失败阈值 | 模型越来越强，复杂题仍可能高正确率 | “难”必须落在模型弱点上 | 先验证核心失败机制 |
| Rubric 设计 | 标准拆得多但权重分散、重复或主观 | Rubric 会直接决定失败率和质检结果 | 原子化、无重叠、可追溯 |
| 质检返修 | 问题分轮出现、反馈理由变化 | 局部修补容易引入新矛盾 | 每次返修做全题回归检查 |
| 时间与收益 | 6—11 小时零收益案例与有收入案例并存 | 单题标价无法代表有效时薪 | 设时间盒与退出线 |
| 岗位匹配 | 多个岗位申请失败很常见 | 专业标签不等于平台认为匹配 | 只申请证据最强的方向 |
| 同质化 | 重复使用同一“坑点”可能失效或被拒 | 套路会衰减，模型也可能变化 | 建立机制库而非题目模板库 |
| 数据与知识产权 | 用户担忧失败成果去向；官方规则转让权利 | 提交前就应按不可撤回资产管理 | 不上传不可授权材料 |
| 证据与申诉 | 返修期限、质检意见、结算状态影响权益 | 情绪描述不能替代证据 | 留存非敏感流程证据 |
| 宣传偏差 | 正向帖、负向帖都可能有选择性 | 不能用单帖推算通过率或收入 | 用自己的 3 题试跑数据判断 |

## 五、当前公开规则划出的硬边界

官方依据：[TalentsAI《用户协议》](https://www.talents-ai.com/user-agreement.html)

截至本次调研，公开协议给出的关键边界如下：

1. 《隐私政策》《数据提交用户协议》、项目说明、任务指南和培训文档都属于平台规则的一部分；
2. 只有经平台或最终客户验收合格的交付成果才计入计费，返工或拒收任务可不支付费用；
3. 除项目另有约定外，协议写的是按月结算，并明确不保证特定时间到账；帖子里出现的“周三结算”等只能视为具体时期或项目经验；
4. 平台拥有交付质量的最终判定权；
5. 当前协议将提示词、问题、答案、标签、评分、修改意见等都纳入“交付成果”；
6. 协议称交付成果的数据权益和知识产权自成果产生之日起归平台或其指定方，并限制用户保留、公开或二次利用副本；
7. 协议同时承诺，尚未验收或未通过验收的成果不会用于模型训练，但验收、反作弊、风控和合规审查所需处理除外；
8. 未经授权的生成式 AI、自动化脚本、爬虫、随机点击、复制粘贴刷单等行为可能导致任务无效或账号处罚；
9. 平台提供注销通道，并写明可通过 `support@talents-ai.com` 申请注销；账号注销后部分信息依法删除或匿名化，法定留存信息除外；
10. 某些高敏感任务可能要求录屏；协议称相关录屏原则上自题目结算之日起保留 60 个自然日，可按规则申请删除，但删除不改变已形成的反作弊认定。

### 与外部帖子冲突时怎么处理

- **“每轮本地备份题目”与“不得保留交付成果副本”冲突。** 不直接照搬帖子做法。只留规则版本、任务 ID、状态、返修期限、质检意见、结算记录等非敏感流程证据；题目正文、材料和答案是否可以留存，必须看项目规则或取得书面许可。
- **“失败成果被用于训练”与官方公开承诺冲突。** 不做无证据定性。若输出在返修后明显变化，记录时间、模型标识、输入版本和可公开的差异描述，通过正式渠道询问；不要把模型随机性、版本变化或上下文变化直接等同于在线训练。
- **“有余额无法注销”与公开注销条款并不一致。** 需要实际查看账户注销页面、余额处理说明和客服书面回复，不能仅凭评论下结论。
- **“周三结算”与公开协议的默认按月结算不同。** 优先遵循具体项目页面的书面结算规则，并在开工前截图留存。

## 六、顶级玩家的核心能力模型

### 1. 项目筛选能力：只打有结构优势的仗

接任务前先回答五个问题：

1. 我是否真正熟悉这个业务流程、文档类型和错误模式？
2. 题目是否能在不依赖主观审美或不确定现实裁量的情况下唯一判分？
3. 我是否合法拥有或可以使用所需材料？
4. 是否存在可在 30—60 分钟内验证的模型弱点？
5. 按最坏返修次数估算，期望有效时薪是否仍高于自己的最低标准？

有任一项无法回答，就先不写完整题。

### 2. 规则工程能力：把自然语言变成机器可验收合同

一份高质量 Prompt 至少应明确：

- **任务目标：** 最终要产出什么；
- **材料边界：** 只能使用哪些文件、区块、版本，是否允许常识补充；
- **优先级：** 系统规则、全局规则、局部规则、后续修订发生冲突时谁优先；
- **版本映射：** 旧版、修订说明、新版如何关联；
- **字段规范：** 字段名、顺序、类型、枚举值、缺失值写法；
- **计算规范：** 单位、精度、四舍五入、日期和时区；
- **格式规范：** 表格、列表、Markdown、加粗、斜体、字数计算口径；
- **异常处理：** 材料冲突、证据不足、重复记录、无法判断时如何输出；
- **禁止事项：** 不得引用材料外信息、不得改写字段名、不得新增解释等；
- **验收示例：** 只演示格式，不泄露真实答案或直接复制通过样题。

“请全面分析”“请专业判断”“给出合理建议”通常不够封闭。把它们改成可计数、可定位、可比对的动作。

### 3. 失败机制设计能力：复杂但不含糊

#### 多轮指令遵循

优先测试以下机制：

- **作用域保持：** 全局规则是否持续约束后续局部任务；
- **优先级切换：** 后续指令只修改一个字段，其他旧规则是否仍保留；
- **撤销与恢复：** 明确撤销某条规则后，模型是否错误地全部重置；
- **长度组合：** 全局总长度、局部固定长度、扩写与缩写并存；
- **格式继承：** 新增段落或表格是否继承斜体、加粗、删除线等要求；
- **同步更新：** A 变化时 B、索引、汇总值和交叉引用是否全部同步；
- **跨轮引用：** 早期定义的枚举、别名或映射在后续是否被遗忘；
- **干扰隔离：** 无关话题出现后，任务状态是否被污染。

设计原则：每个陷阱都必须有明确、合理的业务动机。单纯堆砌人为冲突、故意制造不可满足条件，既容易被模型识别，也容易被质检判为不真实或不合理。

#### 多材料长文

优先使用：

- 政策旧版 + 修订通知 + 新版；
- 合同正文 + 补充协议 + 审批记录；
- 主数据表 + 变更日志 + 对账结果；
- 多部门材料中的同名字段、单位转换和版本冲突；
- 长文本与结构化表格的复合核验。

高质量证据链必须满足：

1. 每个答案字段都能定位到材料；
2. 旧值、变化动作和新值能够连成完整链路；
3. 冲突时有唯一优先级；
4. 缺失证据时有固定输出，不靠猜；
5. Trajectory 中使用的每份材料都对最终答案有真实贡献；
6. Trajectory 与 Answer 的字段、顺序、数值和结论完全一致。

#### 多模态、API/MCP 与复杂环境

评论区认为这些方向更容易暴露模型弱点，但它们同时带来更高的复现和质检风险。只有在项目明确支持对应工具、环境可稳定复现、评分能自动或人工核验、素材授权完整时才值得做。不要仅因“模型可能更容易错”就选一个自己无法验证的复杂环境。

### 4. Rubric 设计能力：不要用低价值评分项稀释失败率

推荐每条 Rubric 使用统一格式：

| 字段 | 要求 |
|---|---|
| ID | 唯一编号 |
| 原子行为 | 一条标准只判断一个行为 |
| 证据位置 | 指向材料、规则或对话轮次 |
| 正确条件 | 可以明确判断“满足/不满足” |
| 失败触发 | 写出会被扣分的具体表现 |
| 权重 | 与业务重要性、项目规则一致 |

检查重点：

- 不使用“足够详细”“基本正确”“表达专业”等主观词；
- 不把同一错误在多个评分项重复扣分；
- 不把模型轻易满足的装饰性要求拆成大量低难度项；
- 每条标准必须来自 Prompt 或材料，不能只存在于参考答案中；
- 先统计预期会失败的权重占比，再决定是否值得写完整题；
- 评分阈值、模型数量和失败条件以当前项目页面为准，不能把帖子中的 70% 永久化。

### 5. 质检应对能力：修一处，回归全题

每次返修按以下顺序处理：

1. 把反馈分类为“根本结构问题、规则缺失、材料问题、Rubric 问题、格式问题、模型失败率问题”；
2. 判断它是否会影响其他字段、材料或评分项；
3. 修改后重新做全链路一致性检查，而不是只改被点名的句子；
4. 记录本轮反馈与上轮是否矛盾；
5. 检查返修截止时间和剩余次数；
6. 如果后期才出现对题目基础逻辑的根本否定，先评估止损或申诉，不要无上限继续补丁式返修。

## 七、项目类型选择建议

| 项目类型 | 优势 | 主要风险 | 更适合谁 | 推荐度 |
|---|---|---|---|---|
| 多轮指令遵循 | 材料准备相对少，机制测试直接 | 强模型正确率高、陷阱易同质化、规则冲突易被质检否定 | 擅长逻辑、状态机和格式约束的人 | 中等，先做小型机制验证 |
| 阿加莎类多材料长文 | 可利用真实专业流程和版本证据链 | 材料准备重、质检轮次多、知识产权风险高 | 熟悉文档审查、财务、政策、合同、制造流程的人 | 较高，但必须有材料优势 |
| VLM 多模态 | 可能存在明显视觉理解弱点 | 素材授权、标注歧义和复现难度高 | 有图像业务经验且项目明确支持的人 | 谨慎 |
| API/MCP/复杂环境 | 能测试真实操作和工具调用 | 环境漂移、失败原因难归因、验收成本高 | 能稳定搭建和验证环境的人 | 仅在规则明确时选择 |
| 法律裁量/开放咨询 | 专业价值高 | 答案天然不唯一，容易被判过度开放 | 能把问题压缩为条款抽取、版本适用或字段核验的人 | 避免开放问法，改造成封闭任务 |

## 八、推荐工作流

### 阶段 0：开工前规则快照

确认并记录：

- 项目名称、岗位、任务 ID；
- 当期规则版本和更新时间；
- 单题价格、奖励条件、结算周期；
- 模型失败阈值和参与模型数量；
- 返修次数、返修截止时间和逾期后果；
- 是否允许生成式 AI、自动化工具、外部资料；
- 材料授权、保密、知识产权和本地副本要求；
- 申诉入口、客服渠道和注销流程。

### 阶段 1：只验证核心失败机制

先用最小场景验证一个机制，不写完整长文。记录：

- 预期模型在哪里失败；
- 这个失败是否可重复；
- 对应哪条 Rubric；
- 失败权重能否达到项目阈值；
- 是否存在同样合理的另一种答案。

如果核心机制无法稳定触发失败，立即换机制或换项目，不要靠无限增加上下文碰运气。

### 阶段 2：封闭化与材料构造

先写答案模式和证据链，再写 Prompt，最后补业务叙事。这样能防止“故事很真实，但答案无法唯一判定”。材料应保留真实世界的冗余和噪声，但所有噪声都不应破坏唯一答案。

### 阶段 3：人工预演

在项目不允许外部 AI 时，不要让其他生成式 AI 代做或润色交付内容。用人工方式模拟至少三种失败输出：

1. 遗漏旧规则；
2. 只满足最新要求；
3. 格式正确但证据或联动字段错误。

逐条运行 Rubric，确认每项都能客观判断。

### 阶段 4：提交与返修

- 提交前执行一次材料—Prompt—Trajectory—Answer—Rubric 五方一致性检查；
- 收到反馈后先判断根因，再修改；
- 每次修改都重新检查全部评分项；
- 截止时间至少预留一个完整回归周期；
- 发现根本逻辑被否定时，重新估算剩余期望收益。

### 阶段 5：复盘

只保留合规的抽象经验：

- 哪类机制有效；
- 哪类表达容易被判开放；
- 哪类 Rubric 会重复或稀释权重；
- 实际用时、返修轮次、结算金额；
- 哪些规则发生变化。

不要建立可复用的真实题目库或私自保留交付成果正文。

## 九、止损机制

以下是建议线，不是平台规则，可按自己的最低时薪调整。

### 单题止损

- 30—45 分钟仍无法把答案封闭到唯一结果：放弃或重构；
- 两次核心机制试验后，模型失败权重仍明显达不到阈值：换机制，不扩写；
- 返修反馈否定了题目的根本业务逻辑：先重新计算剩余收益，不惯性继续；
- 新反馈与旧反馈直接矛盾且无法通过规则解释：整理证据，先申诉或退出；
- 已接近截止时间，却没有完整回归时间：不要仓促提交一个高概率拒收版本。

### 三题试跑法

前 3 题只用于判断个人—项目匹配度，记录：

- 主动投入时间；
- AI 质检轮次；
- 人工质检轮次；
- 是否通过；
- 实际结算和到账时间；
- 返修时限造成的机会成本。

三题后再计算：

```text
通过率 = 通过题数 / 总提交题数

有效时薪 = 已确认结算金额 /（培训 + 选题 + 材料 + 出题 + 返修 + 申诉的主动时间）

预计单题价值 = 个人通过率 × 平均结算额 − 平均额外成本
```

如果有效时薪连续低于你的最低标准，不要被高额单题标价或沉没成本绑架。

## 十、证据留存与申诉

### 合规证据清单

在不违反保密和副本限制的前提下，优先保留：

- 任务 ID、项目名、规则版本和规则更新时间；
- 页面展示的价格、奖励条件和结算周期；
- 提交、返修、通过、拒收的时间戳；
- 返修截止时间及逾期后果；
- 质检原文、申诉原文、客服书面回复；
- 钱包变动、待结算、提现记录；
- 不包含题目正文或敏感材料的状态截图。

建议文件名：

```text
YYYY-MM-DD_任务ID_规则版本_事件类型_轮次.png
```

例如：

```text
2026-09-10_146918_v3_专家返修_第2轮.png
```

不要留存或公开：完整题目、标准答案、客户材料、商业秘密、个人信息、平台禁止保留的交付成果副本。若截图不可避免地包含这些内容，应先确认项目规则和书面许可，并做最小化、脱敏和期限管理。

### 申诉模板

```text
主题：任务【任务 ID】第【N】轮质检结果复核申请

1. 规则依据：引用当期项目规则的具体条款与版本时间。
2. 事实时间线：提交、反馈、返修和截止时间。
3. 争议点：本轮反馈与哪一条规则、上一轮反馈或页面状态不一致。
4. 已完成修订：逐项说明，不提交无关信息。
5. 请求：请确认最终适用规则、一次性列出剩余问题，并复核是否满足结算条件。
6. 附件：仅附非敏感、符合规则的截图或记录。
```

申诉要围绕“规则—事实—差异—请求”，不要只表达愤怒，也不要提出无法证明的“故意白嫖”指控。

## 十一、红旗与绿旗

### 应立即警惕的红旗

- 结算条件只在宣传页出现，任务页没有书面规则；
- 题目价格高，但失败阈值、返修次数、截止时间不清；
- 质检反馈互相矛盾或不断新增根本性要求；
- 任务要求使用你无权提供的内部资料、客户数据或个人信息；
- 项目要求与公开协议冲突，却没有书面解释；
- 需要你使用未经授权的 AI、脚本、多账号或规避检测；
- 题目无法形成唯一答案，只能依赖“专家感觉”；
- 模型失败只能靠不合理矛盾、随机性或不可复现环境获得。

### 值得继续投入的绿旗

- 项目规则可下载或可留存，版本与时间清晰；
- 平台提供结构相似的通过样例和明确反例；
- Rubric 可原子判断，失败阈值可计算；
- 返修次数、截止时间和结算周期明确；
- 你拥有独特专业材料理解力，且材料可合法使用；
- 核心失败机制在小型验证中稳定出现；
- 前三题的个人通过率和有效时薪达到目标。

## 十二、最容易踩的坑，以及替代做法

| 坑 | 为什么危险 | 替代做法 |
|---|---|---|
| 先写完整故事，再想答案 | 容易出现开放答案或证据缺口 | 先写答案模式和证据链 |
| 用长度代替难度 | 上下文更长但模型仍全对 | 测试高耦合、跨轮同步机制 |
| 把评分项拆得越多越好 | 简单项会稀释失败率 | 只保留重要、原子、可验证项 |
| 每次只修质检指出的一句 | 容易引入新的全局冲突 | 每轮做五方一致性回归 |
| 无限返修，期待下一轮通过 | 沉没成本快速扩大 | 设置时间盒和根本问题退出线 |
| 用其他 AI 代写或批量生成 | 可能直接违反项目和用户协议 | 仅使用明确授权的工具 |
| 从网上搬真实公司文件 | 可能侵犯知识产权、隐私或商业秘密 | 用获授权、匿名化、可合法使用的材料 |
| 本地完整保存所有版本 | 可能违反交付成果副本限制 | 只留合规的非敏感流程证据 |
| 复制通过样题 | 易构成同质化、作弊或侵权 | 只抽取结构和验收逻辑 |
| 用单个帖子判断平台 | 存在营销、幸存者和情绪偏差 | 用自己的三题数据做决策 |

## 十三、提交前终检清单

### 规则与合规

- [ ] 已确认当期项目规则、模型、阈值、返修次数和截止时间；
- [ ] 已确认是否允许生成式 AI 或自动化工具；
- [ ] 所有材料可合法使用，已删除个人信息和真实商业敏感信息；
- [ ] 没有保留或准备公开平台禁止留存的交付成果副本。

### Prompt

- [ ] 任务目标唯一；
- [ ] 材料边界明确；
- [ ] 冲突优先级明确；
- [ ] 版本映射明确；
- [ ] 字段、顺序、枚举、单位、精度和格式明确；
- [ ] 缺失与异常处理明确；
- [ ] 禁止事项明确；
- [ ] 不存在互相冲突或无法同时满足的要求。

### 材料与证据链

- [ ] 每个答案字段都有证据；
- [ ] 旧值—修订—新值链路完整；
- [ ] 冗余和噪声不破坏唯一答案；
- [ ] 所有材料在 Trajectory 中有合理用途。

### Answer 与 Rubric

- [ ] Answer 完全符合字段和格式；
- [ ] Trajectory 与 Answer 一致；
- [ ] 每条 Rubric 只测一个行为；
- [ ] 没有主观词和重复扣分；
- [ ] 每条 Rubric 可定位到规则或材料；
- [ ] 预期失败权重达到当期项目阈值；
- [ ] 已人工模拟至少 3 种跑偏输出。

### 提交与收益

- [ ] 已预留至少一次完整回归时间；
- [ ] 已记录非敏感规则与状态证据；
- [ ] 当前预计有效时薪仍高于个人底线；
- [ ] 如果本轮被根本否定，已有明确的申诉或退出条件。

## 十四、最终策略

把 TalentsAI 当作一个“按验收结果付费的高风险专业数据项目”，而不是普通按小时兼职。顶级玩家的优势不在于熬夜次数，而在于：

1. 能快速淘汰不适合自己的项目；
2. 能把专业问题压缩成唯一可判的规则系统；
3. 能在写完整题前验证模型失败机制；
4. 能设计高价值、无重叠的 Rubric；
5. 能对每轮返修做全局回归；
6. 能严格管理时间、证据、授权和知识产权；
7. 能用自己的通过率和有效时薪做决策，不被单题标价、情绪帖子或沉没成本左右。

最重要的一句是：**先验证“这题为什么会稳定失败且仍可唯一判分”，再投入时间把它写完整。**
